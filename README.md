# QR 미션 공통 엔진 — 위안부 「증언: 다음 페이지」

명세 v1.0 (2026.10.05) 기준으로 만든 **공통 엔진 + 위안부 설정 파일**입니다.

```
qr-mission/
├── index.html              화면 8종이 들어 있는 한 장짜리 페이지
├── assets/
│   ├── engine.css          공통 스타일 (색·폰트는 설정에서 주입)
│   └── engine.js           공통 로직 (세션·플로우·결과 산정)
├── config/
│   └── wianbu.json         ★ 위안부 설정 — 문항·문구·색이 전부 여기 있습니다
└── _tools/serve.js         미리보기용 서버
```

**코드를 건드리지 않고 `config/wianbu.json` 만 고치면** 문항·해설·문구·색이 바뀝니다.
박인환·K-컬처는 `config/inje.json`, `config/kculture.json` 을 추가하면 같은 엔진이 그대로 돌아갑니다.

---

## 톤 원칙을 코드로 지킨 부분

명세의 "보물찾기·미션 성공·퀴즈·정답 표현 사용 안 함" 원칙을 구조로 막아 두었습니다.

| 원칙 | 구현 |
|---|---|
| 정답·오답 표현 없음 | 해설 화면 제목은 선택과 무관하게 항상 `tone.correctLabel`("기록에 따르면"). 맞고 틀림을 화면에 쓰지 않습니다 |
| 점수·축하 효과 없음 | `tone.celebrate: false`. 색종이·효과음·진동 코드가 아예 없습니다 |
| 전환은 페이드만 | CSS 애니메이션은 `fade` 하나뿐이며, 동작 줄이기 설정에서는 그것도 끕니다 |
| "페이지를 넘기다" 통일 | 모든 버튼·안내 문구가 설정 파일에만 있고 "획득·성공" 어휘를 쓰지 않습니다 |
| 나비·꽃 상징 제외 | 키비주얼 자리에 금지 문구를 명시해 두었습니다 |
| 재시도·감점 없음 | 기준답과 다르게 골라도 해설만 보여 주고 그대로 통과합니다 |

## 확인한 동작

| 항목 | 결과 |
|---|---|
| 시작 → 6개 스팟 → 결과 → 마무리 전 과정 | ✅ |
| 기준답과 다른 선택 | ✅ "기록에 따르면 / 1992년" 동일 안내, 통과 |
| 유형 산정 (태그 합산 → 최다) | ✅ L 3표 → 「듣는 사람」 |
| 결과 1회 생성 후 고정 | ✅ 다시 들어가도 재계산하지 않음 |
| 이미 모은 스팟 재스캔 | ✅ "이미 넘긴 페이지입니다" → 보드 |
| 토큰 불일치 | ✅ "페이지를 찾지 못했습니다" |
| 중간 이탈 | ✅ 취향 문항까지 마쳐야 수집 인정 |
| 이어 하기 번호 6자리 | ✅ 보드에 표시 |

## 지금 바로 보기

```bash
node _tools/serve.js
```

**링크 하나로 끝까지 볼 수 있습니다.**

```
http://localhost:8780/?p=wianbu&s=s1&t=CHANGE-ME-1
```

닉네임 입력 → 1번 문항 → 획득 화면의 **"다음 QR 찍기 (시연용)"** 버튼을 누르면 2번으로 이어집니다.
6장을 모으면 결과와 마무리까지 그대로 진행됩니다.

| 주소 | 화면 |
|---|---|
| `?p=wianbu` | 보드 (세션이 없으면 시작) |
| `?p=wianbu&s=s1&t=CHANGE-ME-1` | 1번 QR을 찍은 상황 |
| `/wianbu/s/s1?t=CHANGE-ME-1` | 명세의 주소 형태도 동작 |

처음부터 다시 보려면 브라우저 콘솔에서 `localStorage.clear()` 후 새로고침하세요.

### ⚠️ 시연 모드 — 현장 배포 전에 꺼야 합니다

`config/wianbu.json` 의 **`"prototype": true`** 가 켜져 있으면:

- 획득 화면에 "다음 QR 찍기 (시연용)" 버튼이 나옵니다
- 보드에서 아직 안 연 페이지를 눌러 그 QR을 찍은 것으로 처리할 수 있습니다

QR 없이도 전 과정을 볼 수 있어 컨펌·검토용으로 편하지만, **현장에서는 QR을 안 찍고도
수집이 되므로 반드시 `false` 로 바꾸세요.**

## QR 주소

명세의 `/{project}/s/{spotId}?t={token}` 형태를 그대로 쓰되, 서버 없이도 되도록
`?p=wianbu&s=s1&t=토큰` 형태도 인식합니다. **둘 다 같은 화면으로 갑니다.**

⚠️ **토큰은 반드시 바꾸세요.** 지금은 `CHANGE-ME-1` ~ `CHANGE-ME-6` 입니다.
`config/wianbu.json` 의 `spots[].token` 을 발급값으로 교체한 뒤 QR을 만드시면 됩니다.

## 서버 연결 (선택)

지금은 **이 기기에만 저장하는 시연 모드**입니다. 발주처 컨펌용으로는 이대로 충분합니다.

`config/wianbu.json` 의 `api.baseUrl` 에 주소를 넣으면 명세의 엔드포인트로 같이 보냅니다.
화면은 서버 응답을 기다리지 않으므로, 서버가 없거나 느려도 관람에는 지장이 없습니다.

| 호출 | 시점 |
|---|---|
| `POST /api/session` | 닉네임 입력 후 |
| `POST /api/answer` | 스팟 응답 저장 |
| `POST /api/complete` | 결과 생성 |
| `POST /api/message` | 2,745번째 기록 전송 |

**서버가 있어야 되는 것**: 관리자 통계, 기기가 바뀌었을 때 이어 하기 번호로 복구,
전시 메시지 시스템 연동. 지금은 이어 하기 번호를 만들어 보여 주기만 합니다.

## 아직 비어 있는 것 (명세의 "확인 필요" 항목)

문구를 임의로 지어내지 않고 **자리만 만들어 두었습니다.** 확정되면 설정 파일만 바꾸면 됩니다.

| 위치 | 내용 |
|---|---|
| `result.types[].curation` | 남는 문장 · 서고의 숲 도서 · 웹진 「결」 글 · WebXR 주소 |
| 키비주얼 · 페이지 일러스트 · 결과 카드 | 디자인 확정 후 이미지 연결 |
| `spots[].token` | 발급값으로 교체 |
| `period` | 운영 기간 (개막일 10.21 / 10.23 결정 후) |
| `finish.messages` | 승인본 문장 목록으로 교체 |

### 원고를 다듬은 곳 — 확인 부탁드립니다

명세 원문을 그대로 쓰되, 화면에 들어가려면 문장이 되어야 하는 부분만 손봤습니다.

1. **3번 문항 해설** — 원문 `김복동·강일출·이옥선·송신도·길원옥 님` → 호칭 원칙("님")에 따라
   `김복동 님, 강일출 님, 이옥선 님, 송신도 님, 길원옥 님의 목소리입니다.` 로 풀었습니다.
   **명세의 "증언자 표기 순서 확인" 항목과 함께 확인이 필요합니다.**
2. **5번 문항 해설** — 원문의 "숫자 카드 수록 여부 확인 후 확정"은 내부 메모로 보고 화면에서 뺐습니다.
3. **관람객용 위치 안내** — 시공 메모(`placeNote`, 예: "암전 공간 내부 금지")가 관람객에게 보이면
   안 되므로 `hint` 를 따로 두었습니다. 보드의 "다음 페이지"에는 `hint` 만 나옵니다.

| 스팟 | 관람객에게 보이는 안내 |
|---|---|
| 1 서문 연표 | 연표 통로 끝 |
| 2 1부 2744개 기록 | 기록 벽 옆 |
| 3 2부 증언의 바다 | 출구 쪽 |
| 4 2부 삶이 보여준 증언 | 복도 끝 |
| 5 3부 기억이 된 기록 | 숫자 카드 책상 옆 |
| 6 3부 서고의 숲 | 서가 옆 |

## 설정 파일 읽는 법

| 키 | 뜻 |
|---|---|
| `theme` | 색·폰트·모서리. 화면에 CSS 변수로 들어갑니다 |
| `tone` | 문항 라벨, 해설 제목, 축하 연출 여부 |
| `strings` | 화면에 나오는 모든 문구 |
| `spots[]` | QR 6곳. 위치·토큰·수집품·지식 문항·취향 문항 |
| `spots[].knowledge.answer` | 기준 답의 순번(0부터). 화면에는 정답으로 표시되지 않습니다 |
| `spots[].preference.options[].tag` | L 듣다 / R 기록하다 / T 전하다 / Q 묻다 |
| `result.types` | 태그별 유형 이름·설명·큐레이션 |
| `finish.mode` | `message` = 선택형 메시지 (위안부) |
